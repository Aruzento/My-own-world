Source audit: [REPOSITORY_MAINTAINABILITY_AUDIT_0.0.1.9.0.md](../02-architecture/REPOSITORY_MAINTAINABILITY_AUDIT_0.0.1.9.0.md)

Status: `CLEANUP ACTIVE`

Owner approved starting `0.0.1.10.0` cleanup on 2026-08-11. Work remains one RCB leaf at a time: confirm the finding on current code, add regression coverage, fix the real owner, update docs, commit, then stop before the next RCB.

## Rules For 0.0.1.10.0

- One cleanup leaf, one responsibility, one commit.
- Cleanup must not add product functionality.
- Cleanup must preserve persistent data format unless a separate owner-approved migration task exists.
- Prefer fixing correctness/data-safety before visual or stylistic cleanup.
- Do not move tracked historical docs into local `legacy/`.
- Do not create broad generic utility buckets just because several files have similar helpers.
- Do not use this backlog as permission for NF work, combat, dice, collaboration, graph concept changes, map feature work or product redesign.

## Not Cleanup Without New Approval

These are not approved by this backlog:

- new product features;
- combat/dice/effects implementation;
- collaboration or server sync;
- new graph concept;
- map workflow redesign;
- broad CSS rewrite;
- broad Knowledge Graph rewrite;
- new dependency installation;
- persistent format migration;
- moving `docs/archive/` or tracked history into ignored `legacy/`.
